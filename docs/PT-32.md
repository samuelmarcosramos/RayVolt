# PT-32 — Fleet management foundation

Source: PT-32 acceptance criteria supplied in the Jira screenshot and section 4.3
of `TQS26- Product Specs report.docx`.

The architecture is a modular Spring Boot monolith. Fleet owns scooter lifecycle
rules. Packages within `com.rayvolt.backend.fleet` separate model, service and
repository responsibilities. No MQTT or other module internals enter Fleet.

This increment implements the model and service only, without new dependencies.
The service is not registered as a Spring bean until a real repository exists.
No production in-memory database or unprotected operator endpoint is exposed.
Retirement updates state rather than deleting the scooter. Retired scooters cannot
be edited or retired again; this is an explicit conservative lifecycle choice.
Scooter types remain nonblank strings until the type catalogue is specified.
