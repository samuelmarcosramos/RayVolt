# PT-32 — Fleet management

Source: PT-32 acceptance criteria supplied in the Jira screenshot and section 4.3
of `TQS26- Product Specs report.docx`.

## Architecture

Fleet follows the modular Spring Boot monolith: controller → service → repository.
The model contains lifecycle rules; the service orchestrates changes; the JDBC
repository uses PostgreSQL. Flyway owns schema evolution in `db/migration`.
JDBC keeps the existing immutable model independent of persistence annotations.

Each fleet operation runs in a transaction. An exclusive table lock on hubs and
scooters serializes writes, preserving hub capacity and scooter state. Reads remain
possible. This deliberately simple approach limits write throughput; replace it
with coordinated row locking if fleet write volume requires it. Future booking,
trip and hub services must read and change state inside a compatible transaction.

Retirement updates state without deleting the scooter or its ID. Retired scooters
release capacity. In-use, reserved and retired scooters cannot be edited or retired.
A type-only edit at the same hub remains possible when the hub is full.
Types are nonblank strings pending a type catalogue. All non-retired scooters
count toward their assigned hub's capacity, including reserved/in-use scooters;
confirm physical occupancy semantics when Trips is implemented.

## API

These endpoints currently have no authentication. TODO: enforce operator access
through the Users module before deploying outside local development.

| Method | Path | Result |
| --- | --- | --- |
| POST | `/api/scooters` | 201 with scooter JSON and Location |
| PUT | `/api/scooters/{id}` | 200 with updated scooter JSON |
| DELETE | `/api/scooters/{id}` | 204; logical retirement |

POST and PUT body: `{"type":"Standard","hubId":"<existing-hub-uuid>"}`.
The response contains `id`, `type`, `hubId`, `status`.
There is no GET endpoint yet. Location identifies the created resource.
Invalid JSON, blank/missing type, missing/invalid UUID → 400.
Unknown scooter or destination hub → 404. Full hub or forbidden state → 409.
Error responses use Spring ProblemDetail.

## Local database

Set `DB_PASSWORD` in the shell, then run `docker compose up --build`.
Compose binds PostgreSQL and the backend to localhost only. Database data persists
in the `postgres_data` volume; restarting does not discard scooters.
For a backend started outside Compose, run `docker compose up -d database`, then
`cd backend && ./mvnw spring-boot:run`. Defaults: PostgreSQL on localhost:5432,
database/user `rayvolt`; override with `DB_URL` and `DB_USERNAME`.
Flyway creates the schema automatically. Existing databases without Flyway history
need a reviewed migration plan; automatic baselining is not enabled.

There is no hub management API or seeded production data. For local testing,
insert a synthetic hub using psql:

```sh
docker compose exec database psql -U rayvolt -d rayvolt -c \
  "INSERT INTO hubs VALUES ('00000000-0000-0000-0000-000000000001', 'Synthetic hub', 2);"
```

## Acceptance coverage

All suites are tagged `PT-32`. `./mvnw test` runs unit/HTTP tests without Docker.
`./mvnw verify` also runs `PostgresFleetRepositoryIT` with Testcontainers PostgreSQL.

| Acceptance criterion | Automated coverage |
| --- | --- |
| Add scooter with type/hub, initially available | FleetServiceTest.addedScooterStartsAvailable; FleetControllerTest.createReturnsLocationAndAvailableScooter |
| Edit type/hub unless reserved/in use | FleetServiceTest.protectedStatesRejectChanges; PostgresFleetRepositoryIT.movesPersistAndReservedScootersCannotRetire |
| Reject addition/move to full hub | FleetServiceTest.fullHubRejectsAdditionAndMoveButAllowsTypeChange; PostgresFleetRepositoryIT.capacityBoundariesAndRetirementPersist, concurrentAddsCannotOverfillLastSpace |
| Retire, hide from users, prohibit booking, keep history | FleetServiceTest.retirementKeepsIdentityAndHidesScooter; PostgresFleetRepositoryIT.capacityBoundariesAndRetirementPersist; user queries/booking/history integration pending |
| Reject retirement of reserved/in-use scooter | FleetServiceTest.protectedStatesRejectChanges; PostgresFleetRepositoryIT.movesPersistAndReservedScootersCannotRetire |

Integration tests also cover unknown hubs and transaction rollback. HTTP tests
cover status codes, request validation and error responses.
